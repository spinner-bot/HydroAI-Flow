# README 动画头图设计方案

> 依据 `docs/spec/UI 设计理念.md` 的强制设计流程编写：先设计、再编码，本方案单独 commit 后才会落地为代码。
> 产物：`assets/hero.svg`（动画头图） + `README.md`（引用头图；正文已于 2026-09-24 清空，见 §8 已知取舍）。

---

## 0. 约束前提（技术事实，先于美学决策）

| 约束 | 结论 |
| --- | --- |
| GitHub 会清洗 markdown 中的内联 `<svg>` | 头图必须是独立 `.svg` 文件，用 `<img>` 引用 |
| SVG 中的 `<script>` 在图片上下文永不执行 | 动画只能用纯声明式 CSS `@keyframes`，不能用 JS |
| `<img>` 上下文不加载外部网络字体 | 字体栈只能是系统字体，见 §2 |
| README 由读者浏览器的主题决定底色 | 头图做成自带底色的独立卡片，不依赖页面底色 |

> 最后一条是本方案最关键的结构性决策：**头图是一张自带深色底、自带描边圆角的独立卡片**，而不是一张透明贴图。
> 这样它在 GitHub 亮色主题和暗色主题下呈现完全一致，不需要维护亮/暗两套素材。

## 1. 美学方向

**Linear 的暗色网格底 + Stripe 的多层径向光晕 + 紧凑负字距的展示级标题。**

不新造视觉语言。本项目 `meeting/9221-收集预备/demo v3.html` 已经确立了这套语言（深青底、薄荷色强调、网格叠加、环 + 有机核的 hero），头图是它的延续，不是平行设计。

明确排除的方向：

- 不用 emoji 徽章墙（违反 `docs/spec/UI 设计理念.md`「禁止 emoji 充当图标」）
- 不用居中对称 + 等分卡片模板（违反「避免千篇一律的居中对称 + 等分卡片模板」）
- 不用纯装饰性炫技动效（违反「动效服务于体验，不为炫技而存在」）

## 2. 字体系统

字体栈与 demo v3.html 完全一致，保证同源：

```
Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif
```

- **展示级（Wordmark）**：字重 800，负字距 `-0.035em`。拉丁文字用 `-0.07em`（demo 的取值）会挤压到粘连，故按拉丁字形单独放宽。
- **正文级**：17px / 字重 400，行高 1.6。
- **标签级（eyebrow / 标签片）**：11px / 字重 700 / 字距 `+0.2em` / 全大写。用正字距与展示级标题形成对比。

字号层级对比：62 / 17 / 11，比值约 5.6 : 1.5 : 1，跨度过档明确。

> 因外部字体在 `<img>` 上下文不可加载，所有文本按 `Inter` 缺失、回退到系统字体的情况预留了宽度余量（见 §4），不会因字体回退而溢出。

## 3. 色彩系统

色值全部来自 demo v3.html（多数取自其 `:root`，光晕与核球色取自其 `body` 背景与 `h1` 渐变），不引入 demo 之外的色板。
`assets/hero.svg` 的 `:root` 中声明以下 16 个颜色 Token，与下表一一对应：

| Token | 色值 | 来源 | 用途 |
| --- | --- | --- | --- |
| `--bg-0` | `#061117` | demo `:root` | 渐变起点 |
| `--bg-1` | `#0a2029` | demo `:root` | 渐变中段 |
| `--bg-2` | `#071419` | demo `:root` | 渐变终点 |
| `--line` | `#ffffff1c` | demo `:root` | 描边、分隔线、网格线 |
| `--text` | `#effffc` | demo `:root` | 主文字 |
| `--muted` | `#8ca9ab` | demo `:root` | 次级文字 |
| `--mint` | `#70efd5` | demo `:root` | 主强调色（品牌） |
| `--blue` | `#72c9ff` | demo `:root` | 次级强调（渐变收尾） |
| `--mint-soft` | `#a8e9e1` | demo `h1` 渐变 | wordmark 渐变中段 |
| `--glow-a` | `#218c84` | demo `body` 背景 | 左上径向光晕 |
| `--glow-b` | `#5552b6` | demo `body` 背景 | 右下径向光晕 |
| `--core-0` | `#d4fff6` | demo `.core` 渐变 | 核球高光 |
| `--core-2` | `#3389a7` | demo `.core` 渐变 | 核球中调 |
| `--core-3` | `#20234e` | demo `.core` 渐变 | 核球暗部 |
| `--mask-show` | `#ffffff` | 新增 | 网格遮罩可见端 |
| `--mask-hide` | `#000000` | 新增 | 网格遮罩隐去端 |

两处对 demo 的刻意收敛，均不改变观感：

- demo 的 `.core` 渐变第二个色标为 `#70eed7`，与 `--mint` `#70efd5` 仅差 2/255，属重复定义。本方案统一用 `--mint`，消除该重复。
- demo 的网格线用 `#ffffff08`（3%），描边用 `--line`（11%）。本方案不为网格单开 Token，改用 `--line` + `stroke-opacity:.28` 合成出同等的约 3%。

`--mask-show` / `--mask-hide` 并非设计色，而是遮罩的覆盖度通道（白可见、黑隐去），单独列出仅为满足「色值只在 `:root` 定义」的校验规则。

强调色使用克制：头图中薄荷色只出现在 ①eyebrow 前缀线 ②标签片当前态 ③核球光晕 ④第一层波。其余全为文字层级灰。

字色对比度（对 `#061117` 底，WCAG AA 正文需 4.5:1）：

- `--text` `#effffc` → 约 **16.5:1** ✅
- `--muted` `#8ca9ab` → 约 **7.4:1** ✅
- `--mint` `#70efd5` → 约 **12.9:1** ✅

**实现底线**：所有色值只允许在 `<style>` 的 `:root` 中定义一次，其余位置一律 `var(--x)` 引用。交付前会用脚本校验文件中不存在 `:root` 之外的硬编码色值。

## 4. 布局策略

画布 `1200 × 440`（宽高比约 2.73:1，适合 README 全宽展示）。

**非对称左右分区，比例为 52 : 48，但视觉重心偏左。**

```
┌──────────────────────────────────────────────────────────┐
│  ── WATER DYNAMICS · AI SURROGATE MODELING               │
│                                                          │
│  HydroAI-Flow                        ╭─────────╮         │
│  AI-assisted Hydrodynamic            │ ◜ 环 ◝ │         │
│  Modeling & Simulation               │  ◉ 核  │         │
│                                      │ ◟ 环 ◞ │         │
│  [数值模拟] [代理模型] [参数率定]     ╰─────────╯         │
│                                                          │
│  ∿∿∿∿∿∿∿∿∿ 波 场（三层，错速流动）∿∿∿∿∿∿∿∿∿∿∿∿∿∿∿∿  │
└──────────────────────────────────────────────────────────┘
```

- **左区**（`x=76`，可用宽 560）：eyebrow → wordmark → 副标题 → 标签片行。四段纵向排列，间距按 §6 的 8px 节奏。
- **右区**（圆心 `x=930, y=200`）：同心环 155 / 108，有机核球 r=72。
- **底部波场**（`y=320 → 440`）：三层正弦波带，横向错速流动，右侧渐隐。

不在左侧堆叠统计数字或虚构指标——仓库当前没有可量化的成绩，写入即是造假。

标签片内容取自 `meeting/9221-收集预备/组会确认内容收集.md` 的真实议题分组：**数值模拟 / 代理模型 / 参数率定**，是项目已确定的三条主线，不是装饰性占位词。

## 5. 动效策略

**统一缓动**：`cubic-bezier(.22,.8,.25,1)`（与 demo v3.html 完全一致），定义为 `--ease`。

**统一时长刻度**（三档，不出现刻度外的取值）：

| Token | 取值 | 用途 | 缓动 |
| --- | --- | --- | --- |
| `--dur-short` | `6s` | 核球浮动 + 光晕呼吸 | `--ease` |
| `--dur-mid` | `18s` | 虚线环反向旋转 | `linear` |
| `--dur-long` | `28s` | 实线环正向旋转 | `linear` |
| `--flow-front` | `16s` | 最前层波 + 核球内水线 | `linear` |
| `--flow-mid` | `22s` | 中间层波 | `linear` |
| `--flow-back` | `30s` | 最后层波 | `linear` |

> 旋转与波场用 `linear` 而非 `--ease` 是刻意的：循环动画的位移必须恒定速度，否则每圈首尾会出现速度突变。`--ease` 只用于非循环的往复动画（核球浮动）。

**每个动效都必须有信息含义**，逐条对应：

1. **波场三层错速**（`--flow-back/mid/front`）→ 水体分层流动，项目的研究对象本身。视差速度差同时建立纵深。
2. **核球内三条水线横流**（`--flow-front`）→ 核球内部不是静止的球体，而是持续流动的水体。
3. **核球 + 同心环**（`--dur-long` / `--dur-mid`）→ AI 代理模型；环的旋转代表推断过程持续运转。
4. **核球光晕呼吸**（`--dur-short`）→ 模型"活着"，与静态图标区分。

**静态构图元素**（不参与动效，仅承载语义）：

- **计算域网格**（48px）→ 数值模拟的离散化计算域。它是场景的底纹而非动效，因此不占用上面的动效清单。经实渲染核对，其可见度约 3%，与 demo 一致，刻意保持克制。

**尊重系统减少动画设置**：`@media (prefers-reduced-motion: reduce)` 内全部动画降级为静态定格——不是关掉元素，而是保留完整构图、取消位移。信息不因关闭动效而丢失。

## 6. 间距与排版

基准单位 **8px**，所有间距取值均为 8 的倍数或其半数（4px），不出现刻度外数值：

| 位置 | 取值 |
| --- | --- |
| 画布内边距（左/上） | 76 / 124 |
| eyebrow → wordmark | 28 |
| wordmark → 副标题 | 20 |
| 副标题 → 标签片行 | 24 |
| 标签片内边距 | 12 × 18 |
| 标签片间距 | 8 |

圆角：画布 20，标签片 10（与 demo 的 `.mark` / `.tools button` 一致）。
描边：统一 `1px`，色 `--line`。

## 7. 状态覆盖

本头图是**静态展示素材，不存在交互**，因此 hover / focus / pressed / disabled / loading / error 六个交互态不适用——不虚构不存在的状态。

实际存在的状态维度只有两个，均已覆盖：

| 状态维度 | 设计 |
| --- | --- |
| GitHub 亮色主题 | 卡片自带深色底，呈现不变 |
| GitHub 暗色主题 | 同上，呈现不变 |
| 系统"减少动画"开启 | 构图完整保留，所有位移/旋转动画停止 |
| 字体回退（无 Inter） | 按系统字体预留宽度余量，不溢出、不错位 |

## 8. 无障碍

- SVG 根节点带 `role="img"`，内含 `<title>` 与 `<desc>`，为读屏软件提供完整描述。
- 关闭动效后信息完整（见 §5）。
- 全部文字对比度达 WCAG AA（见 §3）。

### 已知取舍：README 正文为纯图像（2026-09-24 起）

README 正文已清空、只保留头图，且**一定时间内不考虑恢复文字**。这使本节原先的一条承诺不再成立：原方案要求「头图中的全部文字信息在 README 正文中均有对应纯文本，不依赖图像传达唯一信息」，**该条已作废**。

当前实际的信息兜底情况：

| 信息 | 载体 | 读屏可获取 | 图片加载失败时 |
| --- | --- | --- | --- |
| 项目名 HydroAI-Flow | 头图 `<text>` + `<img alt>` | ✅ 经 `alt` | ✅ 经 `alt` |
| 副标题 | 头图 `<text>` + `<img alt>` | ✅ 经 `alt` | ✅ 经 `alt` |
| 三条主线标签 | **仅头图 `<text>`** | ❌ | ❌ |

- `<img>` 的 `alt` 为「HydroAI-Flow — AI-assisted Hydrodynamic Modeling & Simulation」，项目名与副标题**有兜底**。
- 三条主线（数值模拟 / 代理模型 / 参数率定）**无任何文本兜底**，读屏用户与关闭图片加载的用户都取不到。
- SVG 内部的 `<title>` / `<desc>` 在 `<img>` 引用方式下**不被主流读屏软件播报**（该方式下由 `alt` 决定），不能算作有效兜底。

这是一项**已知且被接受的取舍，不是疏漏**。若日后需要重新满足原承诺，最小改动是在 `<img>` 之后补一行纯文本，或把三条主线并入 `alt`——两种改法都**不需要改动头图本身**。
