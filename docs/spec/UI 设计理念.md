# 前端设计生成规范

> 本文件为 AI 辅助编码的视觉设计规范。在生成任何前端页面/组件代码之前，必须先阅读并遵循本规范。

## 核心原则

- 所有设计必须有明确的美学意图，禁止输出训练数据中的高频默认模板
- 大胆的极繁和精致的极简都可以，关键是有意为之，而非无脑堆砌
- 先设计，再编码。写代码前必须先输出设计方案（放到仓库并单独 commit）

---

## 强制设计流程

在编写任何前端代码之前，必须先完成以下设计决策：

### 1. 美学方向

选择明确的设计风格方向，禁止使用"现代"、"简洁"、"高级感"等模糊词。可参考成熟品牌的设计语言（如 Stripe / Linear / Vercel / Apple），直接引用品牌名比抽象描述更有效。

### 2. 字体系统

- 标题与正文使用有辨识度的字体搭配，避免无差异化的默认字体
- 中文字体需单独考虑，标题与正文区分对待
- 字号层级需有明确的视觉对比

### 3. 色彩系统

- 色彩方案需给出具体色值，禁止使用语义模糊的颜色描述
- 强调色克制使用，避免调色板过于花哨
- 灰色系需有清晰的分层，保证信息层级可读

### 4. 布局策略

- 布局应有设计意图，避免千篇一律的居中对称 + 等分卡片模板
- 合理利用桌面端屏幕空间，不要简单套用移动端思维

### 5. 动效策略

- 动效服务于体验，不为炫技而存在
- 动画时长和缓动风格需保持统一
- 必须尊重系统的"减少动画"设置

### 6. 间距与排版

- 间距需遵循统一的节奏，禁止随意取值
- 行高、最大阅读宽度等需保证长时间阅读的舒适性

### 7. 状态覆盖

每个交互组件必须包含完整的状态设计（默认、悬停、聚焦、按下、禁用、加载中、错误），不可遗漏。

---

## 代码底线

- 色值必须通过变量或 Token 引用，禁止硬编码
- 图标使用专业图标库，禁止 emoji 充当图标
- 显示/隐藏切换必须有过渡动画，不可生硬跳变
